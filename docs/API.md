# Mory API

The local API is served by `mory start` at `http://127.0.0.1:8787` by default.
All `/v1/*` routes require `Authorization: Bearer <token>`. The token is
generated by `mory init` and stored in the local Mory configuration directory.

## Core endpoints

### `POST /v1/memories/remember`

Extract and store durable memories from an agent input.

```json
{
  "text": "The project uses SQLite as its local source of truth.",
  "source": "mcp",
  "actor": { "type": "agent", "id": "my-agent" },
  "scope": { "projectId": "mory" },
  "metadata": { "importance": "high" }
}
```

### `POST /v1/memories/search`

Search memories using keyword matching and optional embeddings.

```json
{ "query": "SQLite source of truth", "scope": { "projectId": "mory" }, "limit": 10 }
```

### `POST /v1/context`

Return ranked memories and prompt-ready context text for an agent.

### `GET /v1/memories`

List recent active memories. Supports `projectId`, `userId`, and `limit`.

### `GET /v1/memories/:id`

Retrieve one memory.

### `DELETE /v1/memories/:id`

Create a tombstone delete. Historical events remain intact.

### `GET /v1/export` and `POST /v1/import`

Move memories between machines using a versioned JSON export. Import is
deduplicated by content hash and preserves memory IDs where possible.

## Compatibility

The API is local-first and versioned under `/v1`. New fields may be added to
responses without changing existing fields. Clients should ignore unknown
fields and send an explicit `source`, `actor`, and `scope` when available.
